# Tasmota 插头控制台（桌面版）

一个原生桌面窗口程序：**检测连接、控制开关、显示读数**。
纯 Python 标准库（tkinter + urllib），不依赖任何第三方包，不生成网页。

## 启动

```bash
cd ~/WorkBuddy/2026-11-02-09-58-25/tasmota/desktop
./run.sh                              # 读 ~/.config/tasmota/plug.conf
./run.sh --host 192.168.3.46          # 指定地址
```

想放进应用菜单双击启动：

```bash
cp 插头控制台.desktop ~/.local/share/applications/
update-desktop-database ~/.local/share/applications 2>/dev/null || true
```

## 界面构成

| 区域 | 内容 |
|---|---|
| 顶栏 | 标题 + 在线状态灯 + 往返延迟（ms） |
| 工具栏 | 设备地址输入、连接、搜索设备、刷新间隔（1/2/5/10 秒循环切换） |
| 左侧 | 电源控制：大圆钮（点一下切换）、开/关/切换按钮、上电行为 |
| 右侧上 | 六格读数：电压、功率、电流、功率因数、今日用电、累计电量 |
| 右侧下 | 电压 / 功率走势曲线（两条线各自缩放，只反映趋势） |
| 底部 | 运行日志（绿=成功、黄=警告、红=失败）+ 设备信息条 |

## 功能

**检测连接** —— 填 IP 点「连接」，或点「搜索设备」自动扫本机网段。
判定标准是设备返回里有没有 `StatusFWR` 字段，不是靠端口猜测。

**控制开关** —— 主菜单圆钮或三个按钮，走 `cm?cmnd=Power On|Off|Toggle`。

**显示状态** —— 每 2 秒拉一次 `Status 0`（设备信息）+ `Status 8`（计量），
解析 `StatusSTS` / `StatusNET` / `StatusFWR` / `StatusSNS.ENERGY` 四组数据。

## 一个必须知道的坑：用哪个 Python

**必须用系统自带的 `/usr/bin/python3`**，`run.sh` 已经帮你选好了。

原因：这台机器上有两个 Python，它们的 Tk 差别很大。

| Python | Tk | 可见字体数 | 中文 |
|---|---|---|---|
| 托管版 3.13（`~/.workbuddy/binaries/python`） | 9.0 | **20**（只有 X 核心字体） | 全成方块 |
| 系统 `/usr/bin/python3` 3.10 | 8.6 | **239**（含 Noto Sans CJK） | 正常 |

托管版编译 Tk 时没有链接 Xft，只能拿到 `fixed`、`courier` 这类老式 X 字体，
一个中文字体都没有。用系统 Python 就正常。

程序启动时会自检：如果找不到中文字体，日志里会直接给出红字提示。

## 和 `dashboard/` 的区别

| | `dashboard/`（旧） | `desktop/`（本目录） |
|---|---|---|
| 形态 | 网页，跑一个本地 HTTP 服务 | 原生窗口，直接跑 |
| 依赖 | 需要先启动 `server.py` 常驻 | 双击即用，不需要后台服务 |
| 跨平台 | 浏览器打开就行 | Python + tkinter，Windows/Mac 也能跑 |

两者都是只读 + 控制的薄壳，都用 HTTP 直连设备，互不影响，可以同时开。

## 已知限制

- **曲线是"各自缩放"的**：电压几百伏、功率几十瓦，共用一根 Y 轴会把功率压成一条直线。
  所以两条线各自按自己的最大最小值铺满，只看趋势相对变化，不能直接比较高低。
- **图表没做持久化**，关掉程序就清空，最多记 120 个采样点（2 秒间隔 = 4 分钟）。
- **轮询是拉取，不是推送**：设备状态变化最多要等一个轮询周期才反映到界面上。
- **没有温度/电量报警**：要做阈值触发得写进设备的 Rule，不该放在这个界面里。

## 安全提醒

这颗插头**没有任何网页密码**，谁在同一个局域网里知道 IP 谁就能控制。
`app.py` 本身不存任何凭据，也不对外开端口——它只是一个 GUI 客户端。
